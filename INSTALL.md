# Установка и обслуживание сервера

Сервер ставится `scripts/install.sh`. Вход для one-liner'а — `bootstrap.sh` из
релиза: он скачивает `install.sh` и `SHA256SUMS`, сверяет SHA-256 и запускает
установщик с вашими аргументами.

## Совместимость с прежним именем

Проект переименован из CSQTT, но контракты не менялись: package id
`csqtt.quic.amurcanov`, ссылки `csqtt://`, пути `/etc/csqtt`, env `CSQTT_*`,
юниты `csqtt*.service` и бинарники `csqtt`/`csqttctl`. Обновление существующих
установок и APK идёт поверх, без миграции.

## Требования

- Linux **x86_64/amd64**, root.
- Поддерживаются установки **2.5.2+**: источник правды — `/etc/csqtt/install.json`.
- Два режима runtime: `systemd` (по умолчанию) и `docker`.
- Зависимости (`iptables`, `openssl`, `ca-certificates`, `python3` для certbot
  и т.д.) установщик ставит сам.

## One-liner

На Debian/Ubuntu `wget` входит в базовую систему, поэтому он стоит первым:

```bash
sudo bash -c "$(wget -qO- https://github.com/w3struk/recsqtt/releases/latest/download/bootstrap.sh)"
```

Если `wget` нет (Alpine, урезанные образы), тот же скрипт берётся через `curl`:

```bash
sudo bash -c "$(curl -fsSL https://github.com/w3struk/recsqtt/releases/latest/download/bootstrap.sh)"
```

Неинтерактивная установка (CI, cloud-init) — флаги установщика идут после `--`:

```bash
sudo bash -c "$(wget -qO- https://github.com/w3struk/recsqtt/releases/latest/download/bootstrap.sh)" -- --yes
```

Если вы уже root, `sudo` не нужен: `bash -c "$(wget …)"`. Не используйте
`wget … | sudo bash`: пайп занимает stdin, и интерактивные вопросы установщика
(`--host`, пароль панели) ломаются. Без `--yes` нужен настоящий TTY; `--yes` —
неинтерактивный режим.

Входную команду исполняет ваша оболочка **до** запуска `bootstrap.sh`, поэтому
загрузчик для неё выбираете вы, а не скрипт (`bootstrap.sh` выбирает `curl`/`wget`
только для своих внутренних скачиваний). Если на системе нет ни `wget`, ни `curl`
(например, голый `debian:*`-образ без `ca-certificates`), поставьте загрузчик и
корневые сертификаты:

```bash
sudo apt-get update && sudo apt-get install -y wget ca-certificates
```

Без `ca-certificates` `wget`/`curl` падают на проверке TLS — установщик этого
исправить не может, потому что до первого успешного скачивания его ещё нет. На
Debian 13 Minimal `wget` и `ca-certificates` уже входят в базовую систему.

## Интерактивная установка

Без `--yes` в TTY установщик спрашивает по шагам:

1. `Использовать домен для панели? [Y/n]` — `y` или Enter, если домен уже
   указывает A-записью на этот сервер; `n` — IP-режим.
2. `Домен панели (Enter — остаться на IP …)` — домен проверяется по A-записи
   сразу: при несовпадении установщик покажет найденные адреса и переспросит;
   пустой ответ — остаться на IP.
3. Порты туннеля и панели, режим `systemd`/`docker` — Enter оставляет значения
   по умолчанию, неверный ввод переспрашивается.
4. `Настроить логин/пароль/secret path вручную? [y/N]` — `N` генерирует доступы
   и печатает их в конце.

На **уже установленной** панели интерактивный запуск сначала спросит
`Сменить адрес панели (сейчас …)? [y/N]`. Ответ `y` даёт ввести новый домен
или IP: домен проверяется по A-записи, смена режима (46002 ↔ 443) идёт
как reconfiguration, доступы и БД сохраняются. Без `y` сервер просто обновится,
адрес не изменится. Неинтерактивно то же самое:
`bash install.sh --host vpn.example.com --reconfigure --yes`.

## Флаги установщика

| Флаг | Что делает |
| --- | --- |
| `--host <ip\|domain>` | адрес панели; без флага берётся существующий или определяется IP |
| `--mode <systemd\|docker>` | режим runtime (`--docker` — алиас) |
| `--web-port <n>` | порт панели в IP-режиме (по умолчанию 46002; в доменном — 443) |
| `--peer-port <n>` | порт туннеля (по умолчанию 46000) |
| `--check` | только preflight, без изменений |
| `--reconfigure` | разрешить смену host/портов/режима у существующей установки |
| `--yes` | не задавать вопросы |

## Ручной запуск `install.sh`

Для отладки или офлайн-запуска уже скачанного файла:

```bash
wget -qO install.sh https://github.com/w3struk/recsqtt/releases/latest/download/install.sh
sudo bash install.sh --yes
```

`curl -fsSL … -o install.sh` — равнозначная альтернатива, если `wget` нет.

Установщик из ассетов запускайте только через `bash install.sh` — GitHub не
сохраняет бит `+x`. Не запускайте сам `install.sh` через `bash <(wget …)` или
`bash -c "$(wget …)"`: при `sudo` файловый дескриптор process substitution не
пробрасывается, а ~270 КБ скрипта не влезают в один аргумент (`MAX_ARG_STRLEN` —
128 КиБ). One-liner выше запускает `bootstrap.sh` — он и решает обе проблемы.

После установки установщик один раз печатает URL панели, логин и пароль. Повторно:

```bash
sudo csqttctl credentials
```

## Первый клиент и подключение

1. Откройте панель и вкладку **«Клиенты»**.
2. Нажмите **«Создать доступ»** (внутри группы кнопка называется
   **«Создать пароль»**), задайте имя и срок действия.
3. Откройте QR-код клиента или скопируйте ссылку `csqtt://` из его карточки
   (в QR-окне ссылку можно выделить и скопировать).
4. В приложении вставьте ссылку на вкладке **«Туннель»**, отсканируйте QR
   иконкой в шапке экрана или просто откройте ссылку на телефоне — приложение
   сохранит её как конфигурацию подключения.
5. Убедитесь, что в ссылке есть VK-креды — без хешей или токена туннель не
   запустится. Вкладка **«Туннель»** показывает, что пришло со ссылкой:
   «VK хеши из ссылки: N» или «VK токен из ссылки». Если кредов нет, добавьте
   их там же:
   - **«Ссылки VK звонков»** — от 1 до 6 VK-ссылок или хешей (каждый не короче
     16 символов); это ручной режим, хеши хранятся в профиле;
   - **«Вход»** — авторизация в VK: приложение получает токен и запрашивает
     хеши через API; активную сессию можно отозвать кнопкой
     «Сессия VK активна».

   Источник кредов переключает **«Режим хешей»**: автоматически по токену или
   вручную по хешам. В панели те же креды задаются на уровне группы
   («VK токен группы», «VK хеши группы») или отдельному клиенту — тогда они
   попадают в `csqtt://` как `hashes=` / `token=`.

Ссылка `csqtt://` — единственный источник хоста, порта и пароля подключения.
Роль «участник» фиксирована; отдельного серверного профиля в приложении нет.

## `csqttctl`

Установщик кладёт CLI в `/usr/local/lib/csqtt-installer/install.sh` и делает
симлинк `/usr/local/bin/csqttctl`:

```bash
sudo csqttctl status        # режим, версия, порты, служба/контейнер, TUN, сертификат
sudo csqttctl credentials   # URL панели, логин и пароль панели
sudo csqttctl logs [-f]     # журнал установки и лог службы/контейнера
sudo csqttctl panel         # только URL панели
sudo csqttctl update        # скачать свежий install.sh и обновить сервер
sudo csqttctl update --yes  # то же неинтерактивно (CI, без TTY)
sudo csqttctl uninstall     # остановить и удалить runtime, сохранив конфигурацию и БД
sudo csqttctl uninstall --purge  # дополнительно удалить /etc/csqtt
```

`uninstall` не трогает `/etc/letsencrypt`, даже с `--purge`.

## Обновление и откат

- Более старая установка сначала обновляется до 2.5.2, затем — текущей версией.
- Если `csqtt.db` создан старой версией (`schema_version` не равен 2 или поле
  отсутствует), сервер отказывается стартовать и просит сначала поставить 2.5.2.
  Данные и файлы при этом не изменяются.
- `passwords.json`, `passwords.json.imported`, `letsencrypt-ip.env` больше не
  импортируются: установщик сохраняет их как данные. Если БД нет, а JSON старого
  формата есть, сервер отказывается стартовать — иначе поднялась бы пустая панель
  без клиентов.
- `csqtt.db.pre-owner-migration` больше не создаётся; существующая копия
  сохраняется и не читается. Откат на старый бинарник — только восстановлением
  этой копии или снимком runtime.
- Импорт экспорта панели поддерживает только версию 2; файлы старых версий не
  принимаются.

## Пресет RU приложений

Пресет российских приложений лежит в `rust-server/ru_apps_preset.json` и
включается тумблером «Готовый список RU приложений» у правила маршрутизации в
панели. Состав списка правится только в этом JSON-файле: код, протокол и база
данных не трогаются, сервер отдаёт актуальный список в `ROUTING`.

Пресет работает только с клиентом, который понимает `version` 3 протокола
`ROUTING`: поля `preset_red`/`preset_orange` в нём новые, а старый клиент их
игнорирует и пресет не применяет.

## Диагностика

- Установка без `--yes` требует TTY и root; неинтерактивный путь — one-liner
  с `--yes`.
- `sudo csqttctl status` показывает режим, службу/контейнер, TUN и сертификат;
  `sudo csqttctl logs -f` — живой лог службы или контейнера.
- Если панель недоступна, проверьте URL через `sudo csqttctl panel` и порт
  `--web-port` (в доменном режиме панель всегда на 443).
- Пароль панели хранится в `/etc/csqtt/csqtt.env`; если его меняли в панели,
  значение там устарело — используйте новый пароль.
